# Motion Inventory

**Audit date:** November 11, 2026  
**Scope:** Current repository implementation only. Reviewed `src/app`, `src/components/landing`, `src/components/background`, `src/components/navigation`, `src/components/chat`, `src/components/branding`, `src/components/ui/sidebar.tsx`, `src/lib/motion`, `src/lib/performance`, and the existing motion/performance documentation. This is a source inventory, not a runtime profile. No timing, frame-rate, CPU, GPU, or battery measurements were taken or inferred.

## Reading guide

- **Trigger and lifecycle** identify what starts the effect and how it stops where the source supplies that behavior.
- **Cost risk** is a qualitative implementation risk, not a measurement or a claim of user-visible regression.
- “Static frame” means the source renders once and deliberately does not start an animation loop.

## Exact reduced-motion and mobile findings

1. **Global CSS is the broad fallback:** `src/app/globals.css:897-911` reduces CSS animation/transition duration to `1ms`, one iteration, and disables smooth scrolling. `src/components/landing/landing.css:429-436` supplies a landing-scoped equivalent with `.01ms` values and explicitly removes landing menu animations.
2. **Explicit static reduced-motion implementations:** `aurora-gradient-background.tsx` renders a single wave frame; `atmosphere-canvas-engine.tsx` draws a single silk-ribbon frame; the fluted torus disables its loop; both landing reveal coordinators immediately add `.in` when the preference is sampled at initialization.
3. **Explicitly damped, not halted:** `webgl-starfield.tsx` moves to lightweight configuration and disables/lowers several effects; `ambient-canvas.tsx` uses `motionScale = 0.15`; `atmospheric-particles.tsx` freezes particle state but keeps its RAF/draw loop.
4. **Component-level Motion preference coverage is mixed:** chat composer, message item, welcome card, mobile navigation, sidebar dock/sidebar, product preview, and logo read `useReducedMotion`. The inspected landing section components that use `whileInView` do not. `intro-splash.tsx` also has no component-level Motion preference branch.
5. **Mobile-specific reductions observed:** `adaptive-quality.ts` chooses balanced or lightweight tiers based on mobile detection and hardware; `ambient-canvas.tsx` lowers particle count/DPR on narrow screens; `fluted-glass-torus.css` changes visual dimensions at narrow breakpoints. `webgl-planet.tsx` only shows a DPR cap of `2` in the inspected implementation.

## Documentation comparison

- `docs/landing-page/motion-system.md` describes a target system in which all motion snaps to completed state under reduced motion and all continuous motion is limited to transform/opacity. The current source has stronger coverage in some areas, but the assertion is not universally represented in component code: several Motion landing entrances and `IntroSplash` have no local preference branch, and active background systems include canvas/WebGL loops.
- `docs/performance/animation-performance.md` describes adaptive tiering and starfield lifecycle behavior. The inspected `adaptive-quality.ts` and `webgl-starfield.tsx` do implement the documented tiering, tab-visibility pause, intersection pause, and dynamic preference listener. This audit does not validate the document’s performance guarantees because it contains no measurements.
- Existing documentation makes broad performance claims. This inventory intentionally records only code-observable behavior and qualitative cost risks.

## Follow-up candidates for a measured performance pass

These are audit targets, not findings of failure:

1. Profile the high-tier starfield and alternate WebGL planet separately on representative desktop and mobile hardware.
2. Confirm whether pages can mount more than one fixed animated background layer at a time in normal flows.
3. Test reduced-motion behavior in a real browser for Motion components without a local `useReducedMotion` branch, particularly landing in-view entrances and the intro splash.
4. Measure paint/compositing impact of animated `box-shadow`, `backdrop-filter`, and per-frame CSS `backgroundImage` writes.
